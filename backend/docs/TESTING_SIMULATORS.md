# OCPP Симуляторы для тестирования — Предложение

> **Автор**: Эрмек (Backend)
> **Дата**: 2026-02-13
> **Статус**: ОДОБРЕНО оркестратором. Вариант B (ocpp-virtual-charge-point) выбран и протестирован. См. TESTING_RESULTS.md
> **Цель**: Выбрать симулятор зарядных станций для тестирования backend без физического оборудования

---

## Проблема

Backend поддерживает два протокола: **OCPP 1.6J** и **OCPP 2.0.1**.
Для тестирования нужен симулятор, который:
- Подключается к нашему WebSocket серверу (`ws://host:9000/{station_id}`)
- Отправляет сообщения: BootNotification, StartTransaction, MeterValues, StopTransaction
- Поддерживает оба протокола (или хотя бы 1.6)
- Позволяет тестировать: резервирование, enforcement лимитов, ночной тариф, PDF чеки

Без симулятора мы не можем проверить end-to-end flow зарядки.

### Вариант A: SAP e-mobility-charging-stations-simulator

**Репозиторий**: https://github.com/SAP/e-mobility-charging-stations-simulator
**Стек**: Node.js/TypeScript | **Stars**: 208 | **Лицензия**: Apache 2.0

| Критерий | Оценка |
|----------|--------|
| OCPP 1.6 | ✅ Полная поддержка |
| OCPP 2.0.1 | ✅ Полная поддержка |
| Web UI | ✅ Мониторинг + управление |
| Масштабирование | ✅ Десятки/сотни станций через worker threads |
| Автотранзакции | ✅ Автоматический генератор |
| MeterValues | ✅ Реалистичные значения энергии |
| Конфигурация | JSON-шаблоны станций |
| Сложность настройки | Средняя (pnpm + config) |

**Плюсы**: Самый полный симулятор, оба протокола, масштаб, UI.
**Минусы**: Тяжеловат, нужен Node.js/pnpm, сложнее конфигурация.

## Моя рекомендация

### Основной: Вариант B — ocpp-virtual-charge-point

**Почему**:
1. Поддерживает **оба наших протокола** (1.6 + 2.0.1) — критично
2. Простой запуск — 3 env переменных, без сложной конфигурации
3. Schema validation — ловит ошибки в наших ответах
4. Легковесный — не тянет за собой тяжёлый фреймворк
5. Достаточно для текущего этапа разработки

### Дополнительный: Вариант A — SAP simulator

**Когда понадобится**:
- Нагрузочное тестирование (10+ станций одновременно)
- Демо для заказчика (Web UI)
- Тестирование production-сценариев

### Не рекомендую: Варианты C и D

- Нет поддержки OCPP 2.0.1, а у нас dual-protocol

## План интеграции (если одобрено)

1. Клонировать ocpp-virtual-charge-point в `ocpp-rp/tools/simulator/`
2. Написать скрипт `test_charging_flow.sh`:
   - Запуск симулятора v1.6 → BootNotification → Start → MeterValues → Stop
   - Запуск симулятора v2.0.1 → Boot → TransactionEvent(Started/Updated/Ended)
3. Проверить end-to-end:
   - Резервирование 95%/90% при старте
   - Enforcement лимита при MeterValues
   - Ночной тариф (запуск в 23:00+)
   - PDF чек после StopTransaction
   - Partner revenue split
4. Документировать результаты в `docs/TESTING_RESULTS.md`
